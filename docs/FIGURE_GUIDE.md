# 架构与原理图讲解

图解以实际代码为依据，六张图同时用于报告、独立图册和可编辑演示稿。SVG矢量源文件与统一图形数据在 `docs/figures/`，重建命令为 `python -m scripts.build_academic_figures`。数学表达描述当前算法，不声称新的理论定理或训练成果。

| 图 | 回答的问题 | 演示时可以这样解释 |
| --- | --- | --- |
| 1 系统架构与持久化 | 模块如何协作，状态存在哪里？ | 前端提交任务，API验证输入并排队；单个后台执行器依次调用语音识别、片段选择和媒体工具。SQLite保存任务和事件，视频存本地文件。 |
| 2 任务状态机 | 如何知道运行到哪里，何时结束？ | 状态和阶段是两个字段。运行中经历转录、规划、渲染、验证，最终进入完成、待复核或失败。修改指令会复用转录重新运行，不是从中断点恢复。 |
| 3 选择公式与约束 | 为什么选这个片段？ | 当前方法根据主题词与字幕词的加权重合评分，完整短语加分，按阈值选择，再补上下文和合并区间。这是贪心规则，不是训练得到的策略，也不是全局最优解。 |
| 4 来源与输出时间映射 | 剪辑后字幕和来源如何对齐？ | 输出时间等于前面片段总长，加上词在当前源片段中的偏移。例如源32秒的词，在源30秒开始、前序成片4秒的情况下映射到输出6秒。图中数字仅用于解释。 |
| 5 验证与有限修复 | 为什么需要“生成后再检查”？ | 规划给出预期时长，渲染产生实际文件，验证检查实际结果。时长不符时可删可选片段或补语音，最多三次渲染。手动时间线不自动修时长；语义错误不能靠这一循环自动解决。 |
| 6 评估设计 | 如何证明机制有作用？ | 同一批18个开发案例比较三种方法，用单独的区间标注检查内容和约束。在14个可行案例中通过数为1、8、10，但标签由开发者编写，并非独立真实视频基准。 |

建议把16页新版PPT的第11–16页用于技术讲解或答辩备用。每页备注含图注、限制和代码来源。原来的10页偏演示材料仍保留。

必须区分：媒体可解码与语义正确；任务内缓存与长期偏好记忆；规则规划与LLM规划；预训练模型推理与模型训练。正式报告中的图已经嵌入PDF，不依赖阅读器执行Mermaid。
